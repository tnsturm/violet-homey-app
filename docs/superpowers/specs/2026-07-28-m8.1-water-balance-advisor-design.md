# Violet Homey App — M8.1 Wasserbalance-Advisor (Design Spec)

- **Date:** 2026-07-28
- **Status:** Approved design (pending written-spec review)
- **Project:** Homey Pro app for the PoolDigital "Violet" pool controller
- **This spec covers:** Milestone **M8.1** only (advisory module — no writes to the controller).
- **Builds on:** M1 LSI spec (`2026-06-29-violet-homey-app-m1-lsi-design.md`, LSI math in `lib/Lsi.js`), M2 feature groups, M5.7 config-based autoconfig (dosing-channel facts), M5.8 measurement inputs.

---

## 1. Context & goals

M1 tells the user *that* the water is out of balance (LSI + bands). M8.1 tells them **what to do about it**:

- **(a) Fill-water analysis:** starting from the published values of the local waterworks (Gesamthärte °dH, Säurekapazität K_S4,3, pH), compute the tap water's LSI at pool temperature and produce a **startup plan** to bring it into the favorable LSI band — including the CO₂-outgassing warning (fresh tap water is CO₂-rich; the pH climbs as CO₂ escapes, and with low alkalinity the pH swings hard because buffering is poor).
- **(b) Driver analysis:** from the *current* values, identify which lever (pH, total alkalinity, calcium hardness) moves the LSI most per realistic adjustment, and compute **quantified dose recommendations** (grams/millilitres for the configured pool volume) with the side effects of the user's actual dosing products taken into account.

Strictly **advisory**: the module never writes to the Violet. Output per user decision: **Flow action cards with tokens + a timeline notification on band change** (edge-triggered, no spam).

---

## 2. Scope

**In scope**

- New pure module `lib/WaterBalanceAdvisor.js`: unit conversions from waterworks values, dose-factor tables, side-effect matrix, driver ranking, fill-water analysis, CO₂ equilibrium-pH estimate, dilution math. Pure and total (no throws; missing input ⇒ structured `incomplete` result).
- New pure module `lib/WaterBalanceText.js`: renders the structured advisor result into localized text (en/de) for tokens + timeline.
- New settings group **"Wasserbalance-Empfehlungen"**: pool volume, dosing-product dropdowns (pH-Minus type, chlorine type), fill-water values (°dH, K_S4,3, pH, Ca fraction), timeline on/off.
- Two Flow **action** cards: "Get water-balance advice" (`get_balance_advice`) and "Analyze fill water" (`analyze_fill_water`), each returning tokens.
- **Timeline notification** on LSI band change into a non-balanced band (same edge as the existing `lsi_warning` trigger), containing band + top driver + dose amount.
- **Read-only M3/M5.7 coupling:** if a pH dosing channel is detected (existing dosing facts), the advice notes that the Violet regulates pH itself and focuses on TA/CH/CO₂.
- Unit tests for all pure logic (TDD, reference cases against published dosing charts).

**Out of scope**

- Any write to the controller (dosing setpoints via `/setConfig` remain a separate, final milestone per the M3 spec).
- Chlorine/disinfection dosing advice (only *side effects* of the configured chlorine product on the balance are modeled).
- Configurable target bands, PoolLab/LabCOM import (M6), scheduled/digest notifications.
- Salt/TDS handling beyond the fixed 1000 ppm assumption of M1.

## 3. Architecture

Follows the M0/M1 principle: all logic pure in `/lib`, `device.js` thin glue.

```
/lib/
   WaterBalanceAdvisor.js   ← NEW, PURE: conversions, dose factors, driver ranking,
                               fill-water + CO₂ analysis, dilution
   WaterBalanceText.js      ← NEW, PURE: structured result → localized text (en/de)
   Lsi.js                   ← UNCHANGED (single source of LSI truth; advisor calls computeLSI)
/drivers/pool/
   device.js                ← MODIFY: gather inputs, register 2 action cards,
                               timeline notification at the existing band-edge point
   driver.settings.compose.json ← MODIFY: new settings group
/.homeycompose/flow/actions/
   get_balance_advice.json  ← NEW
   analyze_fill_water.json  ← NEW
/test/
   WaterBalanceAdvisor.test.js ← NEW
   WaterBalanceText.test.js    ← NEW
   drivers/pool.device.advisor.test.js ← NEW (wiring: tokens, edge notification, gating)
```

**Invariant:** `lib/Lsi.js` stays the only place LSI math lives. The advisor *predicts* post-dose water states and feeds them through `computeLSI` — it never re-implements the formula.

## 4. Advisor engine (`lib/WaterBalanceAdvisor.js`)

### 4.1 Input conversions (waterworks → LSI units)

| Published value | Unit | Conversion |
|---|---|---|
| Gesamthärte (total hardness) | °dH | × 17.848 → ppm CaCO₃ (total); × Ca-fraction → **calcium hardness ppm** |
| Säurekapazität K_S4,3 | mmol/L | × 50.04 → **total alkalinity ppm CaCO₃** (1 mmol/L acid capacity = 1 meq/L) |
| pH | — | as is |

- **Ca fraction** default **0.75** (typical German drinking water; Ca:Mg hardness ratio ≈ 3:1–4:1), user-adjustable 50–100 %. Documented as an assumption in the setting hint.
- Waterworks that publish "Härtebereich" only (weich/mittel/hart): the hint tells the user to use the exact °dH value from the annual water analysis (Trinkwasseranalyse), which every German utility publishes.

### 4.2 Dose factors (stoichiometric, per m³)

All factors derived from molar masses (CaCO₃ equivalent weight 50.04 g/eq; CaCO₃ 100.09 g/mol) — cross-checked against published pool dosing charts in tests (tolerance ±5 %).

**Raising:**

| Effect | Chemical | Factor |
|---|---|---|
| TA +10 ppm | NaHCO₃ (Natron) | **16.8 g/m³** (84.01/50.04 × 10) |
| pH raise (also TA +10 ppm) | Na₂CO₃ (Soda) | 10.6 g/m³ per 10 ppm TA-equivalent (105.99/(2×50.04) × 10); pH effect estimated via §4.5 and verified via computeLSI |
| CH +10 ppm | CaCl₂·2H₂O | **14.7 g/m³** (147.01/100.09 × 10) |
| pH raise, TA unchanged | **Aeration / CO₂ outgassing** (free) | qualitative measure, always listed when measured pH < equilibrium pH (§4.6) |

**Lowering (acid; 10 ppm TA reduction = 0.2 eq H⁺ per m³):**

| Product (dropdown) | Assumed concentration | Dose per −10 ppm TA per m³ |
|---|---|---|
| Schwefelsäure flüssig (dosing-grade) | 14.9 % w/w, ρ ≈ 1.10 (2 eq/mol) | **≈ 60 mL/m³** |
| Salzsäure | 30 % w/w, ρ ≈ 1.149 | **≈ 21 mL/m³** |
| pH-Minus Granulat (NaHSO₄) | 100 % | **24.0 g/m³** (120.06 × 0.2) |

- Acid recommendations are expressed **primarily as TA reduction** (stoichiometrically exact). The accompanying pH shift is estimated (§4.5) and marked "≈"; the LSI effect is always verified via `computeLSI` on the predicted state.
- Concentration assumptions are fixed per product and stated in the dropdown labels + advice text ("bezogen auf 14,9 % Schwefelsäure"). No free-text concentration field (YAGNI; revisit on user feedback).

**Lowering TA/CH without acid:** partial water exchange (dilution) — §4.7.

### 4.3 Side-effect matrix (configured products)

| Product | pH | TA | CH | CYA |
|---|---|---|---|---|
| Schwefelsäure / Salzsäure / NaHSO₄ | ↓ | ↓ (stoichiometric) | — | — |
| Soda (Na₂CO₃) | ↑ | ↑ | — | — |
| Natron (NaHCO₃) | (≈) | ↑ | — | — |
| CaCl₂ | — | — | ↑ | — |
| Flüssigchlor (NaOCl) | ↑ (slight) | — | — | — |
| Calciumhypochlorit | ↑ (slight) | — | **+0.7 ppm CH per 1 ppm FC** | — |
| Dichlor | ≈ | — | — | **+0.9 ppm CYA per 1 ppm FC** |
| Trichlor | ↓ | ↓ | — | **+0.6 ppm CYA per 1 ppm FC** |
| Salzelektrolyse | ↑ (drift) | — | — | — |

Used two ways: (1) the advice warns about the *long-term drift* the configured chlorine product causes (e.g. Trichlor: "senkt dauerhaft pH/TA und reichert CYA an — TA-Empfehlung fällt darum bewusst an den oberen Rand"); (2) recommended chemicals are chosen consistently with the configured products (never recommend soda for pH if a pH dosing channel exists, etc.).

### 4.4 Driver analysis (`adviseBalance`)

```
adviseBalance({ pH, tempC, chPpm, taPpm, cya, volumeM3, products, dosingCtx })
  → { status, lsiNow, band, drivers[], co2, dilution|null }
```

Algorithm (each step feeds `computeLSI` — no local LSI math):

1. `lsiNow = computeLSI(current)`; `band = classifyLSI(lsiNow)`.
2. For each lever, compute the **clamped ideal target**: the value that would bring the LSI to 0 with all other inputs unchanged, clamped to its practical range:
   - pH* ∈ [7.0, 7.6] (solved from the Carrier form: pH* = pHs, clamped)
   - TA* ∈ [80, 120] ppm (solved via monotonic bisection over computeLSI, clamped)
   - CH* ∈ [200, 400] ppm (same method)
   - Temperature is never a recommendation (not a chemical lever); it is reported as context only.
3. Per lever: `deltaLsi = computeLSI(with lever at target) − lsiNow`. Rank levers by `|deltaLsi|` descending — the top entry is the **driver**.
4. For each lever with `|deltaLsi| ≥ 0.05`: attach the measure — chemical (per product config + side-effect consistency), amount = factor × volume × (target − current)/10, rounded sensibly (g to 10 g, mL to 10 mL). `volumeM3` missing ⇒ `amount: null` (text falls back to "Beckenvolumen in den Einstellungen setzen für Mengenangaben").
5. `dosingCtx.violetDosesPh === true` (a pH-minus or pH-plus dosing channel is detected in the M5.7 facts) ⇒ the pH lever is annotated `handledByViolet: true`; the text explains that the Violet's own dosing regulates pH and the user should adjust the Violet's pH target instead of manual dosing, and the advisor emphasizes TA/CH.
6. `status: 'incomplete'` with a `missing[]` list when required inputs (pH, tempC, chPpm, taPpm) are absent — mirrors `computeLSI`'s null contract, but explains *what* is missing.

### 4.5 pH-shift estimate (documented approximation)

Acid/soda pH predictions use the bicarbonate buffer approximation: the dose is converted to a TA change (exact), and the pH shift is estimated from the ratio of the carbonate-system buffer before/after (`ΔpH ≈ log10(TA_before/TA_after)` for acid within the HCO₃⁻ region, capped at ±0.5 per recommendation step). The text always marks predicted pH with "≈" and the LSI claim comes from `computeLSI`, not from this estimate. Rationale: honest about uncertainty; avoids a full speciation model (approach decision, see §13).

### 4.6 CO₂ outgassing & equilibrium pH (`fill water` and live hint)

- Fresh tap water is typically CO₂-supersaturated relative to air. As CO₂ escapes (splashing, filtration), **pH rises with no alkalinity change**.
- **Equilibrium-pH estimate:** `pH_eq ≈ 6.35 + log10( (TA_ppm / 50044) / 1.43e-5 )` — first carbonic-acid pKa 6.35; dissolved CO₂ at atmospheric equilibrium ≈ 1.43×10⁻⁵ M (420 µatm × K_H 0.034 M/atm). The reported value is `min(pH_eq, 8.4)` and presented as "ca."-value (real pools rarely reach full equilibrium). Example: TA 100 ppm ⇒ raw 8.5 ⇒ reported ≈ 8.4.
- **Poor-buffering warning:** TA < 80 ppm ⇒ explicit warning that pH will swing strongly (little buffering) and that fresh-water top-ups will push pH up noticeably; recommendation order is then always "TA first, pH last, after outgassing has settled (1–2 days of circulation)".
- In `adviseBalance`, when measured pH < pH_eq − 0.3, aeration is listed as a free pH-raising measure (and acid dosing is annotated: "erst nach dem Ausgasen nachmessen").

### 4.7 Fill-water analysis (`adviseFillWater`)

```
adviseFillWater({ dhTotal, ks43, phTap, caFractionPct, tempC, volumeM3, products })
  → { status, chPpm, taPpm, lsiFill, equilibriumPh, plan[], co2 }
```

1. Convert per §4.1 (tempC = current pool temp if available, else the LSI fixed-temperature setting, else 25 °C documented default).
2. `lsiFill = computeLSI(tap values at pool temp)` — the "if you filled today" statement.
3. **Startup plan** (ordered steps, each with amount when volume set): ① adjust TA into 80–120 (NaHCO₃ up / acid down), ② adjust CH into 200–400 (CaCl₂ up; high CH: note dilution won't help — fill water IS the source — recommend accepting a higher CH and compensating via pH/TA), ③ wait for CO₂ outgassing (1–2 days circulation), then ④ set pH to the value that brings the *resulting* water closest to LSI 0 (via computeLSI, clamped [7.0, 7.6]) — with the Violet-doses-pH annotation as in §4.4.
4. The same function powers the **dilution helper**: when `adviseBalance` needs TA/CH *lowered* and fill-water values are configured, it computes the mix (x % exchange ⇒ `new = current × (1−x) + fill × x`) and reports the exchange percentage that reaches the target — plus the honest note when fill water is itself the problem.

### 4.8 Purity contract

Same as `Lsi.js`: all functions pure and total; invalid/missing inputs yield `status:'incomplete'` + `missing[]`, never a throw; all numeric outputs finite or `null`. No I/O, no Homey imports, no Date.now() (caller passes everything).

## 5. Text rendering (`lib/WaterBalanceText.js`)

- Pure formatter: `(advisorResult, lang)` → strings for (a) the full advice token, (b) the compact timeline excerpt (≤ ~180 chars), (c) the fill-water plan token. `lang ∈ {en, de}`, fallback en. Numbers formatted per language (de: comma decimals).
- All strings live here (template functions per language) — settings/compose texts stay inline-bilingual in JSON as before. No i18n framework; two template objects, snapshot-tested.
- Device passes `this.homey.i18n.getLanguage()`.

| id | type | default | notes |
|---|---|---|---|

## 7. Flow cards

### 7.1 Action `get_balance_advice` — „Wasserbalance-Empfehlung berechnen"

- Device action (filter `driver_id=pool`), no arguments.
- Tokens: `advice_text` (string, localized full advice), `top_driver` (string, localized lever name e.g. „Alkalität"), `lsi_now` (number), `lsi_predicted` (number — LSI after applying the top recommendation).
- Stale/incomplete: card **does not throw**; `advice_text` explains what is missing (`status:'incomplete'` path), numeric tokens fall back to `0` with the text stating no valid LSI (Flow tokens cannot be null — documented limitation).

### 7.2 Action `analyze_fill_water` — „Füllwasser analysieren"

- Device action, no arguments (reads the fill-water settings).
- Tokens: `fill_lsi` (number), `equilibrium_ph` (number), `fill_advice_text` (string — startup plan incl. CO₂ note).
- Missing fill-water settings ⇒ same incomplete-text pattern.

### 7.3 Timeline notification

- Fired at the **existing** band-edge point in `device.js` (where `lsi_warning` triggers): band changes into a non-balanced band **and** `advisor_timeline` is on **and** advisor status is `ok`.
- Content: compact excerpt from `WaterBalanceText` — band, top driver, one amount (e.g. „LSI −0,42 (korrosiv). Größter Hebel: Alkalität — ca. 840 g Natron (50 m³) auf 100 ppm anheben.").
- Uses `this.homey.notifications.createNotification({ excerpt })`; failures are caught + logged (notification must never break the poll loop) — first use of the Notifications API in this app.
- No notification on recovery to balanced, on stale, or while incomplete (mirrors `lsi_warning` suppression rules).

## 8. M3/M5.7 read-only coupling

- `device.js` derives `dosingCtx.violetDosesPh` from the **existing** M5.7 feature facts (detected dosing channels; no new reads, no credentials): true when a pH− or pH+ dosing channel is active.
- Effect: pH lever annotated as Violet-managed (§4.4.5). No canister-range coupling in M8.1 (the ranges concern the Violet's own pH/Cl consumables, not the advisor's TA/CH chemicals) — deliberately dropped for YAGNI.

## 9. Error handling

- Advisor + Text modules: pure/total per §4.8 — the poll handler and run listeners never throw because of advice (M0 §10 invariant preserved).
- Timeline `createNotification` wrapped in try/catch (log-only).
- Fresh-gating: advice from live values only when `measurements_fresh` (existing gate); action card on stale data returns the incomplete-text explaining staleness.
- All new settings optional: every missing input degrades to explanatory text, never to an error.

## 11. Testing approach (TDD)

- **`test/WaterBalanceAdvisor.test.js`:**
  - Conversions: °dH→ppm (17.848), K_S4,3→ppm (50.04), Ca-fraction application.
  - Dose factors vs published pool dosing charts (±5 %): NaHCO₃ 16.8 g/m³/10 ppm; CaCl₂·2H₂O 14.7 g/m³/10 ppm; NaHSO₄ 24 g/m³/10 ppm; acid mL/m³ per concentration.
  - Driver ranking: constructed cases where (i) TA is the clear driver, (ii) pH is, (iii) CH is; ties; `|ΔLSI| < 0.05` levers omitted.
  - Target solving: bisection converges; clamps hold (pH* ∈ [7.0,7.6] etc.); predicted post-dose LSI comes from `computeLSI` (spy/equality against direct call).

  - Fill water: full example from a real German waterworks sheet (e.g. 14 °dH, K_S4,3 = 2.5 mmol/L, pH 7.5) — expected CH/TA/LSI documented in the test; step order TA→CH→outgassing→pH.
  - Dilution: mix math; "fill water is the source" honesty case.
  - Side effects: Trichlor annotation, cal-hypo CH note, `violetDosesPh` annotation.
  - Totality: every function with missing/garbage inputs ⇒ `incomplete`/null, never throws.

- **`test/drivers/pool.device.advisor.test.js`:** action cards registered + tokens resolved via mock; timeline fired exactly on band-edge (and not on recovery/stale/disabled); `advisor_timeline` off ⇒ no notification; `lsi_enabled` off ⇒ actions return incomplete text; device released in `after()` (CI listener lesson).

## 13. Decisions log

| Decision | Choice | Rationale |
|---|---|---|
| Output surface | **Flow actions + timeline** (user) | automatable AND zero-config visible |
| Fill-water input format | **Waterworks raw values** (°dH, K_S4,3, pH) + Ca-fraction assumption (user) | users copy the published sheet 1:1; conversion traps live in tested code |
| Notification cadence | **Band-change edge + on-demand action** (user) | consistent with `lsi_warning`, no spam |
| M3 dosing coupling | **Read-only context** (user) | write path is a separate final milestone (M3 spec); zero new risk |
| Engine approach | **A: dose factors + computeLSI verification** (user; over rule-texts / full equilibrium model) | quantified + testable without a speciation model; Lsi.js stays single source of truth |
| Dosing products configurable | dropdowns for pH-Minus + chlorine type (user request) | product side effects materially change the advice |
| Product concentrations | **fixed per dropdown entry, stated in label/text** | YAGNI; a % field adds error surface for marginal gain |
| Equilibrium pH | simple carbonate approximation, capped 8.4, "ca." | honest, cheap, good enough for a warning |
| pH-shift prediction | TA-based buffer approximation, "≈", LSI via computeLSI | avoids overclaiming precision |
| Chlorine dosing advice | **out of scope** (side effects only) | disinfection is the Violet's job; balance is ours |
| Canister-range coupling | dropped | ranges concern Violet's consumables, not advisor chemicals |
| Temperature lever | context only, never recommended | not a chemical measure |

## 14. References

- ANSI/PHTA/ICC-11 — LSI band basis (M1 spec §5).
- Molar masses / stoichiometry: standard values (NaHCO₃ 84.01, Na₂CO₃ 105.99, CaCl₂·2H₂O 147.01, NaHSO₄ 120.06, CaCO₃ 100.09 g/mol; eq weight CaCO₃ 50.04).
- Taylor Technologies / Orenda dosing charts — cross-check targets for §4.2 factors.
- Carbonic-acid system: pKa₁ 6.35; Henry constant CO₂ ≈ 0.034 M/atm; atmospheric CO₂ ≈ 420 µatm (§4.6).
- CYA-per-FC contributions (dichlor ≈ 0.9, trichlor ≈ 0.6, cal-hypo CH ≈ 0.7 ppm per ppm FC) — industry-standard values (Orenda/TFP).
- DIN 19643 (pH 7.0–7.4 operating window) and ANSI/PHTA (7.2–7.8) — the pH clamp [7.0, 7.6] spans the DIN window and the lower ANSI half; documented as the app's own compromise, not attributed to either standard.
